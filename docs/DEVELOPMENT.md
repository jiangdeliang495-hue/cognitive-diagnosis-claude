# 开发过程说明

## 1. 从业务到技术的拆解

目标是从学生作答估计每个知识点的掌握概率，并给出可理解的诊断与学习行动。数据层用 SQLite 长表保存题目与知识点的 Q 矩阵、学生与题目的 X 矩阵、题参及诊断，共 8 张表。固定种子生成 5 个知识点、24 道不同题目、12 名学生和 288 条完整作答；建库按造数、校准、落库依次执行，另存收敛报告，默认拒绝覆盖已有数据库。

算法层采用 DINA：枚举 32 种掌握画像，以 And 门表示一道题所需的全部技能，用对数域后验与约束 EM 校准猜测、失误参数。掌握概率是画像后验的逐技能边际，答对率仅作对照。造数真值不参与估计，也不通过 API 返回；前置图谱解释学习顺序，不裁剪推断空间。

展示层用标准库 HTTP 服务与原生 HTML/CSS/JS，提供雷达图、概率表、前置图谱和 12×5 矩阵。核心 6 个 GET 离线可用。新增模型状态 GET 和建议 POST：只有明确点击才把当前合成学生的诊断快照交给 DeepSeek V4 Pro，开启最高思考；模型提供学习重点、练习行动和检查方法，不改变 DINA 概率。服务只读数据库，关闭连接后才联网，密钥用隐藏输入保留在进程中，建议经过结构校验并以纯文本显示。

## 2. 三个真实问题与纠偏

**测量覆盖缺口。** 初版 Q 矩阵没有仅测 KP5 的题，使“全未掌握”与“仅掌握 KP5”产生相同理想反应。复核后改为三份 I5 加 9 道综合题，并验证 32 种画像的理想反应两两互异。题干同时明确哪些算术结果已给出，防止把暗含多个技能的题标成单技能。

**弱测试放过伪实现。** 只检查返回结构、参数边界和收敛标志，无法证明真的执行 EM。为此加入独立手算的一步更新：K=1、Q=[[1]]、X=[[1],[1],[1],[0]]，期望 g=27/71 截断到 0.35、s=11/254，且似然严格提高；再检查最终题参重算的后验与返回结果一致。独立判据比调用待测函数生成期望值更能发现错误。

**执行环境与异步边界。** Claude 沙箱的端口绑定和 Git 写入受限，HTTP 与浏览器测试改由 Codex 在外部原样执行，权限失败不算业务通过。建议功能复核还发现真实 HTTPResponse 提前 EOF 可能不抛异常，补充剩余长度检查；前端状态查询失败曾被误报为缺密钥，修正为独立错误且重试只发免费 GET。故意注入 500 的迟到日志也曾使测试误报，随后按请求 URL 限定过滤，保留其他页面错误检查。

## 3. SDD、TDD 与 AI 协作的作用

先冻结数据库 Schema、API、数值和 DOM 契约，再写失败测试，最后实现；真实调用的 Superpowers 工作流与阶段 Prompt 均留证。独立复核用于发现测量缺口、弱断言和网络边界，外部测试用于核验实现。部分 UI 回归实际在修复后追加，记录中保留这一顺序，不把局部过程描述成全程完美 TDD。

这次协作说明，AI 能快速生成结构化实现，但正确性来自可复现数据、手算判据、真实失败记录与独立验收。下一次会更早固定 UI 异步与网络传输契约，减少后期补测。合成小样本、固定均匀先验和题参硬区间仍限制结论，不能把一次演示当作课堂准确性证明。
